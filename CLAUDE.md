# PhishGuard — контекст проекта

Общайся со мной на русском. Я студент 3 курса (сетевая безопасность), разбираюсь в ИБ, но не профессиональный разработчик: объясняй, что меняешь и зачем.

## Что это
Веб-сервис: пользователь вставляет текст подозрительного письма/SMS/сообщения, LLM возвращает вердикт (dangerous / suspicious / safe), уверенность, список признаков и рекомендацию. Целевая аудитория — Казахстан.

Прод: https://projectphishquard.vercel.app/

## Стек и архитектура
- Фронтенд: React + Vite + TypeScript (изначально сгенерирован в Bolt.new, дальше развиваем вручную)
- Бэкенд: Supabase Edge Function `analyze-email` (`supabase/functions/analyze-email/index.ts`), вызывает OpenRouter
- Хостинг: Vercel, автодеплой при пуше в `main` на GitHub
- Переменные фронтенда (`.env`, не коммитить): `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`

### Важно про безопасность
- Ключ `OPENROUTER_API_KEY` хранится ТОЛЬКО в секретах Edge Function. Никогда не добавлять его во фронтенд и в `.env` с префиксом VITE_.
- Фронтенд обращается только к Edge Function, не к OpenRouter напрямую.

### Важно про деплой Edge Function
Supabase-проект был создан через Bolt и, похоже, управляется инфраструктурой Bolt — функция `analyze-email` НЕ видна в моём личном дашборде supabase.com. Изменения в `supabase/functions/` в репозитории сами на прод не попадут. Прежде чем менять серверную логику, сначала разберись со мной, как её задеплоить (возможно, придётся перенести функцию в мой собственный Supabase-проект).

## Уже реализовано
- Анализ через LLM со структурированным JSON-ответом
- Калибровка промпта против ложных срабатываний:
  - фраза «никому не говорите код, даже сотруднику банка» — признак ЛЕГИТИМНОСТИ
  - транзакционные SMS с официальными доменами (kaspi.kz, forte.kz, halyk.kz, onay) не считаются подозрительными сами по себе
  - вердикт строится на КОМБИНАЦИИ факторов (подозрительный домен + давление + просьба данных), один нейтральный признак не даёт высокий confidence
  - пустой список признаков → всегда "safe"
- Лимит 5 проверок в день на IP (таблица `rate_limits`, сброс в полночь UTC — так задумано, не переделывать на скользящее окно)
- Обход лимита для админа через `?admin_key=...` (значение в секрете `ADMIN_KEY`)
- Защита от пустого поля, спиннер загрузки
- Лендинг-секция «Не дай себя обмануть»
- Переключатель языков RU / KZ / EN — добавлен в Bolt последним, работоспособность НЕ проверена

## Тестовые сценарии (должны проходить после любых изменений промпта)
- Фишинг с поддельным доменом (kreditbanking-dkb...) → dangerous
- BEC: «начальник на совещании, срочно оплати поставщика» → dangerous
- «Мама Айгерим, она в больнице, переведите 25000» → dangerous
- «Друг с нового номера, срочно 15000 на Kaspi» → suspicious
- Код подтверждения + «никому не говорите» → safe
- Реклама Forte Bank с доменом forte.kz → safe
- «Можешь одолжить 10000 до зарплаты?» → safe
- Тесты на казахском и английском тоже
