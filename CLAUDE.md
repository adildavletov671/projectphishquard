# PhishGuard — контекст проекта

Общайся со мной на русском. Я студент 3 курса (сетевая безопасность), разбираюсь в ИБ, но не профессиональный разработчик: объясняй, что меняешь и зачем.

## Что это
Веб-сервис: пользователь вставляет текст подозрительного письма/SMS/сообщения, LLM возвращает вердикт (dangerous / suspicious / safe), уверенность, список признаков и рекомендацию. Целевая аудитория — Казахстан.

Прод: https://projectphishquard.vercel.app/

## Стек и архитектура
- Фронтенд: React + Vite + TypeScript (изначально сгенерирован в Bolt.new, дальше развиваем вручную)
- Бэкенд: Supabase Edge Function `analyze-email` (`supabase/functions/analyze-email/index.ts`) в моём проекте **projectphishquard** (ref `bajpoetehnbiiugfuygj`, https://bajpoetehnbiiugfuygj.supabase.co). Вызывает OpenRouter, модель `openai/gpt-4o-mini`, `temperature: 0`
- Хостинг: Vercel, автодеплой при пуше в `main` на GitHub (деплоит только фронтенд, НЕ функцию)
- Переменные фронтенда (`.env` локально и Environment Variables в Vercel, не коммитить): `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`
  - `VITE_SUPABASE_ANON_KEY` — **legacy anon key** (JWT `eyJ...`, Settings → API Keys → Legacy). Новый `sb_publishable_...` не подходит: у функции `verify_jwt = true`, шлюз пропустит только JWT
  - Vite встраивает `VITE_*` в сборку: после смены переменных в Vercel нужен Redeploy, локально — перезапуск `npm run dev`
- Прод (Vercel) переключён на этот проект 2026-11-10. Старый Supabase-проект от Bolt (не виден в моём дашборде) больше не используем. Отката на него НЕТ: его ключ OpenRouter удалён 2026-11-10, функция там больше не работает

### Важно про безопасность
- Секреты Edge Function (Dashboard → Edge Functions → Secrets), значения вводит только пользователь, никогда не выводить:
  - `OPENROUTER_API_KEY` — ключ OpenRouter
  - `ADMIN_KEY` — ключ обхода лимита, только буквы и цифры (`openssl rand -hex 32`), иначе ломается в URL
  - `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` Supabase подставляет сам
- Никогда не добавлять эти ключи во фронтенд и в `.env` с префиксом VITE_. Ключ `service_role` во фронтенд — тоже никогда
- Фронтенд обращается только к Edge Function, не к OpenRouter напрямую
- `increment_total_checks()` может вызывать только `service_role` (миграция `20261109120000_harden_increment_total_checks.sql`)

### Деплой бэкенда (Supabase CLI)
CLI стоит как dev-зависимость, запуск через `npx supabase` (после `git pull` на другой машине — `npm install`).
- Первичная настройка на новой машине — в ОТДЕЛЬНОМ терминале (команды интерактивные, через `!` в Claude Code не работают):
  `npx supabase login`, затем `npx supabase link --project-ref bajpoetehnbiiugfuygj` (спросит пароль БД)
- В CLI 3.x команды по умолчанию смотрят в ЛОКАЛЬНУЮ базу (Docker) — для моего проекта всегда `--remote`
- В режиме агента изменяющие команды требуют `--yes` (только после моего подтверждения), чтение — `--read-only`
- Команды:
  - Миграции: `npx supabase migration list --remote` → `npx supabase db push --remote --dry-run` (показать мне) → `npx supabase db push --remote --yes`
  - Функция: `npx supabase functions deploy analyze-email --yes` (предупреждение «Docker is not running» — норма)
  - Секреты (только имена): `npx supabase secrets list`
  - SQL только на чтение: `npx supabase db query --remote --read-only "select ..."`
  - Логи функции: https://supabase.com/dashboard/project/bajpoetehnbiiugfuygj/functions/analyze-email/logs
- Порядок: правка → показать мне дифф → деплой функции → ручные тесты на localhost → коммит

## Уже реализовано
- Анализ через LLM со структурированным JSON-ответом
- Калибровка промпта против ложных срабатываний:
  - фраза «никому не говорите код, даже сотруднику банка» — признак ЛЕГИТИМНОСТИ
  - транзакционные SMS с официальными доменами (kaspi.kz, forte.kz, halyk.kz, onay) не считаются подозрительными сами по себе
  - реклама/рассылки банков, где все ссылки ведут на официальный домен или его поддомен (что-то.forte.kz) и нет просьбы ввести пароль/код/карту/ИИН → "safe"; сроки акции («успейте до…») — маркетинг, не давление. Похожие домены (forte-kz.com, forte.kz.bonus-credit.ru, f0rte.kz) и сокращатели ссылок под это правило НЕ попадают (правило Б2/Ә2/B2 в промпте)
  - вердикт строится на КОМБИНАЦИИ факторов (подозрительный домен + давление + просьба данных), один нейтральный признак не даёт высокий confidence
  - пустой список признаков → всегда "safe"
  - промпт есть в трёх версиях (RU/KZ/EN) — любое правило добавлять во все три
- Лимит 5 проверок в день на IP (таблица `rate_limits`, сброс в полночь UTC — так задумано, не переделывать на скользящее окно)
- Обход лимита для админа через `?admin_key=...` (значение в секрете `ADMIN_KEY`); сервер отвечает `admin: true` без `remaining`, счётчик на фронтенде скрыт
- Ошибки сервер отдаёт кодом (`rate_limit_exceeded`), текст берётся из переводов на фронтенде
- Защита от пустого поля, спиннер загрузки
- Лендинг-секция «Не дай себя обмануть»
- Переключатель языков RU / KZ / EN — проверен. UI из `src/locales/*.json`, модель отвечает на языке интерфейса (`lang` в запросе). При смене языка результат сбрасывается, опоздавший ответ на старом языке отбрасывается
- Счётчик проверок — шаблон `remainingOf` со своим порядком слов в каждом языке (KZ: «5-тен 3»; окончание «-тен» подходит только для лимита 5)
- Названия признаков отображаются с заглавной буквы (на фронтенде)

## Тестовые сценарии (должны проходить после любых изменений промпта)
- Фишинг с поддельным доменом (kreditbanking-dkb...) → dangerous
- BEC: «начальник на совещании, срочно оплати поставщика» → dangerous
- «Мама Айгерим, она в больнице, переведите 25000» → dangerous
- «Друг с нового номера, срочно 15000 на Kaspi» → suspicious
- Код подтверждения + «никому не говорите» → safe
- Реклама Forte Bank с доменом forte.kz → safe
- Та же реклама Forte, но со ссылкой на forte.kz.bonus-credit.ru → НЕ safe (проверка, что правило про рекламу нельзя обойти поддельным доменом)
- «Можешь одолжить 10000 до зарплаты?» → safe
- Тесты на казахском и английском тоже
- Тесты гонять с `?admin_key=...`, чтобы не тратить дневной лимит
